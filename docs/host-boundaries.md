# Host boundaries and resource limits

A2UI.Core and A2UI.Agent validate protocol messages and own session-local state. The application authenticates both endpoints, chooses the applicable negotiation policy, enforces its transport limits and authorises side effects.

## Configure the limits

| Boundary | Default | Host configuration and verification |
| --- | --- | --- |
| Encoded A2UI message | 4 MiB of UTF-8, including whitespace. Oversized input is rejected with `messageTooLarge` before it is read as JSON. | Pass `maxEncodedBytes` to `WireMessage.TryDecode` or `RendererMessageProcessor.ProcessAsync`. Bound the request body before buffering it in the transport. The Core and Agent package smoke apps check both sides of the limit. [Core checks](../tests/PackageSmoke/CoreSmoke.cs) · [Agent checks](../tests/PackageSmoke/AgentSmoke.cs) |
| Component definitions per surface | 10,000, including orphans and reusable template definitions. An over-limit create or update fails atomically with `componentLimit`. | Set `maxComponentsPerSurface` on `SurfaceSession`, `RendererState` or `RequestProcessor.CreateSession`. Forks preserve it. Replacing a definition under the same ID leaves the count unchanged. [Core checks](../tests/PackageSmoke/CoreSmoke.cs) · [Agent checks](../tests/PackageSmoke/AgentSmoke.cs) |
| Materialised component occurrences | 10,000 per tree. Templates can produce several occurrences per definition. | Pass `maxOccurrences` to `SurfaceSession.GetComponentOccurrences`. `NodeResolver` uses the fixed default. [Core checks](../tests/PackageSmoke/CoreSmoke.cs) |
| Component graph and data-model depth | 50 graph edges or container levels, counting the data-model root at depth zero. Component values also have a 50-level limit. A function-call chain inside a component is limited to five calls. | Fixed protocol validation limits. Choose strict or progressive topology separately through `GraphValidationOptions`. [Pinned processor and composition cases](../tests/Conformance/CoreCases.cs) |
| Expression interpolation | 65,536 UTF-16 code units of input, 100 expression levels and 1,048,576 UTF-16 code units of output. | Fixed in `ExpressionTemplate`. Reject larger input earlier in the host when needed. [Expression limit and diagnostic checks](../tests/Conformance/ExpressionChecks.cs) |
| Basic Catalog regular expressions | 256 pattern code points, 4,096 input code points and a one-second match timeout. | Fixed in the Basic Catalog implementation. [Function and regex checks](../tests/Conformance/FunctionCases.cs) |
| JSON Pointer | 63 path segments. Expanding a data-model list is limited to zero-based index 10,000. | Fixed safety limits in Core. [Core data-model checks](../tests/PackageSmoke/CoreSmoke.cs) · [Pinned data-model cases](../tests/Conformance/DataModelCases.cs) |
| Pending calls from renderer to agent | 256 across one `AgentFunctionClient`, with no default per-call timeout. | Set `maxPendingCalls` in the client constructor. Pass `timeout` to `Send` or `CallAsync` when issuing calls directly. The client refuses calls above capacity with `PENDING_LIMIT`. [Core checks](../tests/PackageSmoke/CoreSmoke.cs) · [Pinned RPC cases](../tests/Conformance/RpcCases.cs) |
| Pending calls from agent to renderer | 256 across one `RendererFunctionClient`, with a 30-second per-call timeout. | Use `RendererFunctionClient` or `RequestProcessor.CreateRendererFunctionClient` to set `maxPendingCalls` and `defaultTimeout`. A call can override its timeout. [Pinned renderer-call cases](../tests/Conformance/RendererFunctionCases.cs) |
| Settled reactive agent answers | 256 successful answers per surface. When capacity is reached, a newly settled answer evicts the oldest settled answer. | Pass `maxCachedAgentAnswers` to `FunctionCallRouter`. Pending calls still share identical requests and count against the client capacity. Live bindings retain their current call-site results when the shared cache evicts them. Failures and imperative action calls do not consume cache capacity. [Cache regression](../tests/PackageSmoke/CoreSmoke.cs) |
| Direct JSON streaming response | 1,048,576 UTF-16 code units across all chunks. | Pass `maxCharacters` to `DirectJsonStream`. Apply application-level limits to buffered batch inference results. [Agent streaming checks](../tests/PackageSmoke/AgentSmoke.cs) |
| Inline catalog | 256 KiB per encoded inline catalog, after the host opts in. | Use `CatalogRegistry.TryRegisterInline` on Core or opt in during Agent catalog negotiation. Apply a transport limit to the complete capabilities document. [Core checks](../tests/PackageSmoke/CoreSmoke.cs) · [Agent checks](../tests/PackageSmoke/AgentSmoke.cs) |
| Agent macro expansion | 32 nested expansion levels and 10,000 generated components. | Set `MacroExpanderOptions.MaxDepth` and `MaxComponents` when creating the expander. [Pinned macro cases](../tests/Conformance/MacroCases.cs) |

## Apply host policy

- Resolve schemas from the local registry. Unknown external references fail validation without a network request. Allow inline catalogs only for conversations that need them, and review requirements imposed by the catalog separately from schema validity. [Schema validation](schema-validation.md) · [Core checks](../tests/PackageSmoke/CoreSmoke.cs)
- Use one session and function client per conversation. Route messages, replies and opted-in data-model snapshots only to the authenticated owner. Surface and function call IDs identify objects within their session. [Package isolation checks](../tests/PackageSmoke/CoreSmoke.cs) · [SSE example](../samples/AspNetCoreSse)
- Register host function implementations explicitly. Pass user activation only for a real user gesture. For built-in `openUrl`, supply a host callback if the application supports opening links. It receives only absolute HTTP or HTTPS URLs after activation checks. The host decides where and how to open them. A custom catalog cannot inherit the built-in URL handler without requiring activation. [Core host checks](../tests/PackageSmoke/CoreSmoke.cs) · [Pinned local action cases](../tests/Conformance/OutboundCases.cs)
- The SDKs emit no default telemetry. SDK-generated diagnostics use error categories, structural locations and protocol identifiers. Plain data-model values and ordinary handler exception details are omitted. Identifiers, JSON Pointer segments, peer-provided error messages and intentional `AgentFunctionException` messages can come from application input. When logging, prefer diagnostic codes and counts. Include contextual identifiers only under the application's own data policy. [Core redaction checks](../tests/PackageSmoke/CoreSmoke.cs) · [Agent redaction checks](../tests/PackageSmoke/AgentSmoke.cs)
